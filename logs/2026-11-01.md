## 💡 Concept of the Day

### JSON Web Tokens (JWT) — a signed, self-contained pass for APIs

After you log in to a website or API, the server needs a way to recognise you on every later request without asking for your password again. A JSON Web Token (JWT, pronounced "jot") is one popular answer: a compact string the server issues at login, which the client then sends back, usually in an `Authorization: Bearer <token>` header.

A JWT has three parts, separated by dots: `header.payload.signature`.

- **Header** — says what kind of token this is and which algorithm signed it, for example HS256 (HMAC with SHA-256) or RS256 (RSA with SHA-256).
- **Payload** — the claims: statements about the user, such as a user id, a role, and an expiry time (`exp`). These are Base64Url-encoded, not encrypted, so anyone holding the token can read them.
- **Signature** — created by signing the header and payload with a secret (HMAC) or a private key (RSA/ECDSA). The server verifies this signature on every request, so a tampered token is rejected.

Because the token carries its own claims, the server does not need to look up a session on every request, which is why JWTs are called stateless. That convenience has real trade-offs:

- **Signed is not secret.** Never put passwords or sensitive data in a payload; anyone can decode it.
- **Tokens cannot easily be revoked.** A stolen token stays valid until it expires, so keep access tokens short-lived and pair them with refresh tokens.
- **Verify strictly.** Always check the signature, the expiry, and the algorithm, and never accept the `none` algorithm or let the token's own header choose how it is verified.

## 🛠️ Tool of the Day

### jq — peek inside a JWT from your terminal

`jq` is a command-line JSON processor, and it is handy for inspecting a token's payload without pasting it into a website. The payload is the second dot-separated part, Base64Url-encoded, so decode it and pipe it to `jq`:

```bash
echo "$TOKEN" | cut -d. -f2 | tr '_-' '/+' | \
  awk '{print $0 substr("====", 1, (4 - length % 4) % 4)}' | base64 -d | jq .
```

Try it: decode a token from a project you are building and check its `exp` and role claims. If you see sensitive data in there, that is a bug worth fixing before the token ever ships.
