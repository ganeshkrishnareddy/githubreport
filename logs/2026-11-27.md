## 💡 Concept of the Day


### Idempotency — make retries safe, not scary


Networks fail at the worst moments: your request to charge a customer times out, and you have no idea whether it went through. Retry it blindly and you might charge them twice. **Idempotency** is the property that makes retrying safe — performing the same operation multiple times has the same effect as performing it once.


In HTTP, `GET`, `PUT`, and `DELETE` are idempotent by definition: fetching a resource ten times changes nothing, and deleting something twice leaves it deleted. `POST` is the troublemaker — every call can create a new resource, so a retried payment request can double-charge a customer.


The standard fix is an **idempotency key**: the client generates a unique key (a UUID works well) and sends it with the request, usually as an `Idempotency-Key` header. The server stores the key with the result of the first request. If the same key arrives again, the server returns the stored result instead of running the operation twice.


Three things worth remembering:


- **Keys belong to one logical operation.** Generate a fresh key per operation, and reuse the *same* key only when retrying that exact operation. A new key means a new operation.
- **The server must store the result, not just the key.** A retry should get back the original response — including the original success or error — so the client cannot tell it apart from the first call.
- **It is a design decision, not a library.** Idempotency keys work because the API honours them; check whether the API you call supports them before relying on retries in your code.


## 🛠️ Tool of the Day


### ripgrep (rg) — search your codebase at the speed of thought


**ripgrep** is a line-oriented search tool that recursively searches your project for a regex pattern. It is the modern answer to `grep`: by default it respects your `.gitignore`, skips hidden files and binary files, and searches in parallel — so results arrive in a blink even in huge repositories.


```bash
# Install (macOS / Debian-Ubuntu)
brew install ripgrep        # or: sudo apt install ripgrep

# Find every TODO in Python files, with line numbers
rg -n -tpy TODO

# Search for a pattern, show 2 lines of context around each match
rg -C 2 "def handle_payment"

# List only the file names that contain a match
rg -l "SECRET_KEY"
```


Why it is worth trying:


- **Sane defaults.** No more piping `grep -r` through `--exclude-dir=node_modules` — ripgrep ignores what git ignores, automatically.
- **Fast with Unicode.** Built on Rust's regex engine, it stays fast while handling UTF-8 correctly, where GNU grep often slows down.
- **More than plain search.** Filter by file type (`-tpy`, `-Tjs`), search inside compressed files (`-z`), or switch on PCRE2 regex (`-P`) for look-around and backreferences.


How to try it: install it, then replace one `grep -r` in your daily workflow with `rg` and compare the speed yourself.
