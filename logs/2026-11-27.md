## 💡 Concept of the Day


### Event Sourcing — store what happened, not just what is


Most apps store only the *current* state: a bank account row says the balance is Rs 1,100, but not how it got there. **Event Sourcing** flips that around — instead of storing state, you store every change as an immutable event in a log: `AccountOpened`, `MoneyDeposited(500)`, `MoneyWithdrawn(400)`. The current state is then derived by replaying those events from the start.


The payoff is a complete, trustworthy history. Auditors can see exactly when and why every change happened. Bugs become easier to debug because you can replay the exact sequence of events that led to a bad state. And if an event was recorded wrongly, you can fix it and replay the log to rebuild the correct state.


Three things worth remembering:


- **Events are facts, never edited.** Once written, an event stays in the log forever. Mistakes are corrected by appending a compensating event, not by rewriting history.
- **State is a cache of the log.** You can discard the current state and rebuild it by re-running the events — which is also how you answer "what did this look like last Tuesday?" by replaying only up to that point.
- **It is not free.** Event stores grow forever, replaying long logs is slow without snapshots, and changing the meaning of old events needs care. It shines in audit-heavy domains like finance — and is overkill for a simple CRUD app.


## 🛠️ Tool of the Day


### tmux — a terminal multiplexer that keeps your sessions alive


**tmux** lets you run several terminals inside one window — and, more importantly, keeps them running after you disconnect. Start a long build or a dev server on a remote machine inside tmux, detach, close your laptop, and reattach later to find everything exactly where you left it.


```bash
# Install (macOS / Debian-Ubuntu)
brew install tmux          # or: sudo apt install tmux

# Start a named session
tmux new -s dev

# Inside tmux, all commands start with Ctrl+b (the prefix):
#   Ctrl+b d   detach (session keeps running in the background)
#   Ctrl+b %   split pane vertically
#   Ctrl+b "   split pane horizontally
#   Ctrl+b c   new window

# Reattach later, from anywhere
tmux attach -t dev

# List your sessions
tmux ls
```


Why it is worth trying:


- **Survives dropped connections.** SSH dies, your work does not — the session lives on the server, waiting for you to reattach.
- **One window, many panes.** Editor, server logs, and tests side by side, without juggling terminal tabs.
- **Scriptable and shareable.** Sessions can be scripted in a config file, and two people can attach to the same session for live pair programming.


How to try it: open a terminal, run `tmux`, start a long-running command, detach with `Ctrl+b d`, then reattach with `tmux attach` — you will wonder how you worked without it.
