## 💡 Concept of the Day

### Git Rebase vs Merge — keep your history clean

When your feature branch drifts behind `main`, you have two ways to catch up — and they produce very different histories.

**Merge** creates a new merge commit that ties the two lines of history together. It preserves exactly what happened, but a busy repo ends up with a tangled graph full of merge commits.

**Rebase** replays your commits on top of the latest `main`, one by one, as if you had branched off just now. The result is a straight, linear history that is much easier to read and to `git bisect`.

```bash
git checkout feature
git rebase main        # replay your commits on top of main
git checkout main
git merge feature      # now a clean fast-forward merge
```

The golden rule: **never rebase commits you have already pushed to a shared branch.** Rebase rewrites commit hashes, so teammates who based work on the old history will hit conflicts. Rebase your own private branches freely; merge when the branch is shared.

A handy middle ground is the interactive rebase (`git rebase -i`), which lets you squash, reorder, and reword commits before sharing — turning a messy work-in-progress branch into a clean story.

## 🛠️ Tool of the Day

### lazygit — a terminal UI that makes Git (and rebase) visual

lazygit is a free, open-source terminal UI for Git, written in Go. Instead of memorising flags, you get panels for files, branches, and commits, with every action one keypress away.

Why it is worth trying:

- **Visual interactive rebase.** Press `i` on the commits panel, then `s` to squash, `d` to drop, or `Ctrl+K`/`Ctrl+J` to reorder — no TODO file to edit by hand.
- **Line-level staging.** Stage individual lines with `space` instead of wrestling with `git add -p`.
- **Undo anything.** Press `Ctrl+Z` and lazygit undoes the last operation via the reflog — a safety net for rebase mistakes.

How to try it:

```bash
brew install lazygit            # macOS
# or: go install github.com/jesseduffield/lazygit@latest
lazygit                         # run inside any Git repo
```

Press `?` anytime to see all shortcuts. Start with staging and committing; graduate to interactive rebase once you are comfortable.
