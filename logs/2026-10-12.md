## 💡 Concept of the Day: Zero-Trust Security

**The one-line version:** Stop treating anything "inside" your network as safe — verify *every* request, from *every* user and device, *every* time. "Never trust, always verify."

**The idea:** The old model was a castle and moat: once you were past the firewall, you were trusted to roam. That breaks the moment one laptop gets phished, one VPN credential leaks, or one insider goes rogue — the attacker is already inside, with free movement. Zero trust (formalized in NIST SP 800-207) assumes breach and replaces network location with identity as the perimeter.

**The three principles you'll actually use:**
- **Verify explicitly** — every access decision checks identity (who), device health (what), and context (where, when, why) — not "are you on the office Wi-Fi?"
- **Least privilege** — hand out the smallest access needed, for the shortest time (think 5-minute API tokens, not year-long keys)
- **Assume breach** — design so one compromised account can't move sideways: micro-segmentation, per-request checks, continuous monitoring

**The practical takeaway:** you don't need an enterprise budget to think zero-trust. Short-lived tokens, MFA everywhere, no long-lived secrets in code, and services that authenticate each other (mTLS) are zero-trust habits you can start today.

## 🛠️ Tool of the Day: gitleaks — Catch Secrets Before They Hit Your Repo

**What it is:** gitleaks is a fast, open-source secret scanner. It digs through your git history *and* current files looking for leaked credentials — AWS keys, Stripe tokens, GitHub PATs, private keys, `.env` contents — using built-in rules for all major providers, plus custom regex rules you can add — [github.com/gitleaks/gitleaks](https://github.com/gitleaks/gitleaks)

**Why it's useful:**
- Scans the *full git history*, not just the current files — a secret deleted in commit #50 is still recoverable, and attackers know that
- Runs as a pre-commit hook or in CI, so leaks get blocked before they become permanent
- The "least privilege" habit made automatic: once a secret is committed, the fix isn't deletion — it's *rotation*, so prevention is everything

**How to try it:**
```bash
# install (macOS)
brew install gitleaks

# scan your repo's full history
gitleaks detect --source . --verbose

# block secrets at commit time (pre-commit hook)
gitleaks protect --staged
```
Run it on a personal project today — leaked-key commits in *public* repos are scraped by bots within minutes. Zero-trust starts at the keyboard.
