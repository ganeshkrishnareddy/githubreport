## 💡 Concept of the Day

### Passkeys — passwords, replaced by cryptography

Passwords are the weakest link in most systems: they get reused, phished, and leaked in breaches. **Passkeys** replace them with public-key cryptography, built on the FIDO2 / WebAuthn standards that Apple, Google, and Microsoft now support.

Here is the idea in one paragraph: when you register, your device creates a **key pair** — a private key that never leaves the device, and a public key stored on the server. To sign in, the server sends a random challenge; your device signs it with the private key after you unlock it with a fingerprint, face, or PIN; the server verifies the signature with the public key. Nothing secret ever travels over the network, and there is no password database left to steal.

Three things worth remembering:

- **Phishing resistance is built in.** The signed challenge is bound to the real site’s domain, so a lookalike login page cannot capture anything reusable — the signature simply will not verify for the wrong site.
- **No shared secret to leak.** A server breach exposes only public keys, which are useless on their own. Credential stuffing dies with the password database.
- **Keep a fallback.** Synced passkeys (iCloud Keychain, Google Password Manager) travel across your devices, but losing every device can still lock you out — set up a second device, a security key, or a recovery method before you need one.

## 🛠️ Tool of the Day

### SimpleWebAuthn — add passkeys to a Node.js app without the ceremony

**SimpleWebAuthn** is an open-source TypeScript library that wraps the WebAuthn server and browser APIs, so you do not have to hand-roll attestation and assertion flows. It gives you helpers to generate registration and authentication options on the server, verify the responses, and drive the browser side with a small client package.

```ts
import {
  generateRegistrationOptions,
  verifyRegistrationResponse,
} from '@simplewebauthn/server';

// server: create options, send them to the browser,
// then verify the credential the browser returns
```

Why it is worth trying:

- **One library, both sides.** `@simplewebauthn/server` and `@simplewebauthn/browser` cover the full flow, with examples for Express and Fastify.
- **Sane defaults.** It handles the fiddly parts — challenge generation, origin and RP ID checks, and counter validation — that are easy to get wrong by hand.
- **A gentle on-ramp.** The docs walk through a complete registration and login flow, so you can add passkeys to a side project in an evening.

How to try it: install the two packages, follow the getting-started guide at simplewebauthn.dev, and test the flow with the demo at webauthn.io first.
