## 💡 Concept of the Day

### OAuth 2.0 — let apps act for you, without handing over your password

You click "Sign in with Google" on a new app, approve access to your profile, and the app never sees your Google password. That handshake is OAuth 2.0: a standard for **delegated authorization** — giving a third-party app limited access to your stuff, on your behalf.

Four roles are involved:

- **Resource owner** — you, the user whose data it is.
- **Client** — the app asking for access.
- **Authorization server** — the service that checks who you are and issues tokens (e.g. Google).
- **Resource server** — the API that actually holds your data.

The most common flow, authorization code with PKCE, works like this:

1. The app redirects you to the authorization server, asking for specific **scopes** (e.g. "read your profile", not "everything").
2. You approve. The server sends back a short-lived authorization code.
3. The app exchanges that code (plus a PKCE verifier that proves the request came from the same app) for an **access token**, and often a **refresh token**.
4. The app calls the API with the access token. When it expires, the refresh token gets a new one without bothering you again.

Two things people get wrong:

- **OAuth is not authentication.** It answers "can this app do X for this user?", not "who is this user?" (that layer is OpenID Connect, built on top of OAuth).
- **Scopes are the whole point.** A token that can only read your public profile is far less dangerous if leaked than one with full account access, so always request the narrowest scope that works.

## 🛠️ Tool of the Day

### ripgrep (rg) — grep, built for codebases

[ripgrep](https://github.com/BurntSushi/ripgrep) is a line-oriented search tool written in Rust, and the `rg` command has quietly become the default way to search code. It is fast, but the real win is its defaults: it respects `.gitignore` out of the box, skips hidden files and binary files, and searches in parallel.

```bash
rg "TODO"                 # search the whole project, ignoring gitignored files
rg "fetchUser" -t py      # only Python files
rg "api_key" --hidden -g '!*.lock'   # include hidden files, skip lockfiles
rg "oldName" -l           # just list the files that match
```

Try it as a drop-in for `grep -r` in any repo, and pair it with `fzf` (`rg --files | fzf`) for fast file jumping. Editors like VS Code use ripgrep under the hood for workspace search, so learning its flags pays off twice.
