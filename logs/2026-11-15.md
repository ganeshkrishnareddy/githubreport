# 📝 Daily Log — 15 November 2026

## 💡 Concept of the Day

### SQL Injection — when user input becomes code

SQL injection happens when an app builds a database query by pasting user input straight into the SQL string, instead of treating it as data. The database can no longer tell where the code ends and the input begins — so a crafted input can rewrite the query.

A classic example: a login query like this, with `username` filled in by the user:

```sql
SELECT * FROM users WHERE username = 'admin' AND password = 'secret'
```

If the username is `admin'--`, the query becomes `... WHERE username = 'admin'--' AND ...` — the `--` comments out the password check, and the attacker logs in without knowing the password. The same flaw can leak whole tables, or delete data, depending on the query.

The fix is simple and non-negotiable: **use parameterized queries (prepared statements)**. The SQL structure is sent separately from the values, so the database treats input as data, never as code. Add least-privilege database accounts too, so even a successful injection can reach only what the app truly needs. Never rely on blocking "bad characters" — attackers always find a bypass.

## 🛠️ Tool of the Day

### sqlmap — automate SQL injection testing (on systems you own)

**sqlmap** is an open-source Python tool that automates detecting and exploiting SQL injection flaws. Give it a URL, and it fingerprints the database (MySQL, PostgreSQL, SQL Server, Oracle, SQLite and more), tries boolean-blind, time-blind, error-based, UNION and stacked-query techniques, and can list databases, tables and rows.

```bash
git clone https://github.com/sqlmapproject/sqlmap.git
cd sqlmap
python3 sqlmap.py -u "http://localhost:8080/product?id=1" --dbs
```

Why it is worth trying:

- **Learn by testing, not guessing.** Run it against a lab app you own, such as DVWA or a PortSwigger lab, and see exactly which inputs are injectable.
- **Fast enumeration.** Once a flaw is confirmed, `--tables` and `--dump` show what an attacker could actually reach.
- **A defence tool too.** The findings are the evidence you need to justify parameterized queries to a team.

Only ever run it on systems you own or have explicit written permission to test. Unauthorised testing is illegal.
