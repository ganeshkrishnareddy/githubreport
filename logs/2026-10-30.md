## 💡 Concept of the Day

### Exponential Backoff — retrying without hammering a struggling service

A failed API call is often transient: a brief network blip, a deploy in progress, or a server momentarily overloaded. Retrying immediately feels sensible, but if every client retries at once, the retry traffic itself can finish off the struggling service. That pile-up is called a retry storm.

Exponential backoff fixes the timing. After each failure, wait longer before the next attempt: roughly 1 second, then 2, then 4, then 8, and so on. The growing gaps give the service breathing room to recover, while a quick first retry still handles the genuinely brief blips.

Two refinements make it work in practice:

- **Cap the wait.** Uncapped exponential growth soon means waiting minutes or hours between attempts, so set a maximum delay (for example, 60 seconds) and a maximum number of attempts.
- **Add jitter.** If all clients wait exactly 4 seconds, they all return together and create a new spike. Adding randomness to each wait spreads retries out over time, which is why jittered backoff beats plain backoff.

Also, retry only what is safe to retry. Timeouts and 5xx errors are usually retryable; a 4xx error means the request itself is wrong, so retrying it unchanged will just fail again. And never retry a non-idempotent operation (like charging a card) unless you can prove the first attempt did not go through.

## 🛠️ Tool of the Day

### Tenacity — retries in Python, as a decorator

[Tenacity](https://tenacity.readthedocs.io/en/stable/) is a general-purpose Python retry library. Instead of hand-writing retry loops with `time.sleep`, you describe the policy in a decorator: how many attempts, how long to wait, and which errors to retry.

```python
from tenacity import retry, stop_after_attempt, wait_random_exponential

@retry(
    stop=stop_after_attempt(5),
    wait=wait_random_exponential(multiplier=1, max=60),
    reraise=True,
)
def call_api():
    ...
```

Here the function is tried up to 5 times, waits grow exponentially with randomness (jitter) up to 60 seconds, and the original error is re-raised if all attempts fail. Tenacity also supports stopping after a time limit, retrying on specific exception types or return values, and async functions, so the same decorator scales from a quick script to production code.

Try it: `pip install tenacity`, then wrap one flaky network call in your own project and watch the retry behaviour in your logs.
