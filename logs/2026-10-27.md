## 💡 Concept of the Day

### Debounce vs Throttle — two ways to tame rapid events

A search box fires an event on every keystroke, a scroll handler on every pixel. Running expensive work on each event wastes CPU and floods your API. Two patterns tame the flood, and picking the wrong one causes real bugs.

**Debounce** waits until the events stop. Each new event resets a timer; the work runs only after a quiet period (say 300 ms) with no new events. It is the right choice for search-as-you-type: you only want to query once the user has paused typing, not once per letter.

**Throttle** guarantees a steady pace. It runs the work at most once per interval (say every 200 ms), no matter how many events arrive. It is the right choice for scroll handlers and resize listeners: you want regular updates while the user is still scrolling, not silence until they stop.

A tiny mental model:

- **Debounce** — "Wait until they stop talking, then respond." (search input, form auto-save)
- **Throttle** — "Respond at most once every X ms while they keep talking." (scroll position, mouse move, window resize)

The common mistake is debouncing a scroll handler: the UI then freezes until scrolling stops, which feels broken. And throttling a search box wastes requests on half-typed queries. Match the pattern to the question: do you need the *final* value, or *regular updates along the way*?

Both patterns are a few lines of code by hand, and most utility libraries ship them ready-made.

## 🛠️ Tool of the Day

### bat — a cat clone with wings

[bat](https://github.com/sharkdp/bat) is a `cat` clone with syntax highlighting and Git integration, written in Rust. It prints files the way you actually want to read them in a terminal: highlighted, line-numbered, and aware of your repo.

Why it is useful:

- Syntax highlighting for a large number of languages, out of the box, so reading code in the terminal stops looking like a wall of grey text.
- Git integration: when viewing a file inside a repo, bat marks added, modified, and deleted lines in the gutter.
- It behaves like `cat` when piped (plain output, no paging), so it drops into scripts and pipelines without surprises.

How to try it:

```bash
brew install bat            # macOS
# or: sudo apt install bat  # Debian/Ubuntu (binary may be named batcat)
bat main.py                # highlighted, numbered, paged if long
bat -p README.md           # plain mode, like cat
bat --line-range 40:80 app.js   # show just one slice of a file
```

Pair it with `fzf` as a previewer (`fzf --preview "bat --color=always {}"`) and browsing files from the terminal starts to feel like an IDE's quick-open.
