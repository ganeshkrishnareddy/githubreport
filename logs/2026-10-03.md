# 📝 Daily Log — 3 October 2026

## 💡 Concept of the Day: CRDTs (Conflict-free Replicated Data Types)

**The one-line version:** A CRDT is a data structure designed so that concurrent edits on different replicas merge themselves into the same final state, with no server in the middle and no merge conflicts, no matter what order the edits arrive in.

**How it works:**
- Each replica (your laptop, your phone, a teammate's browser) edits its own copy and broadcasts the changes as small operations or state chunks.
- The merge function is commutative, associative, and idempotent: apply the edits in any order, any number of times, and you always land on the same state. So "you type offline, I type online" resolves itself cleanly when the two sync.
- Two classic families: **state-based** (merge whole states; simple but chatty) and **operation-based** (broadcast small ops; lean but needs reliable delivery).

**Why it matters:** CRDTs are the engine behind local-first, offline-capable collaboration: Google-Docs-style editing that keeps working on a plane and syncs perfectly when you land, with nobody's keystrokes ever lost. The trade-off is a growing history (deleted items leave "tombstones" behind), which implementations compress aggressively.

**A bit of history:** The math was formalized by Marc Shapiro and colleagues at Inria around 2011, turning a research curiosity into a practical building block. A decade later, the Ink & Switch lab's "local-first software" movement made CRDTs the poster child for apps that work without the cloud in the loop.

## 🛠️ Tool of the Day: Yjs

- **What:** Yjs is a high-performance JavaScript CRDT library by Kevin Jahns (@dmonad), built on the YATA algorithm from his GROUP 2016 research paper. It exposes shared types (`Y.Text`, `Y.Map`, `Y.Array`, ...) that you edit locally and sync with peers. Home: https://github.com/yjs/yjs
- **Why it is useful:** It is one of the fastest and most battle-tested CRDT implementations, with ready bindings for editors (TipTap, ProseMirror) and canvas apps (tldraw), plus network providers like `y-websocket` so two browsers sync in real time. Offline edits just queue up and merge later.
- **Try it:** Install it (`npm install yjs`), then share an update between two docs:

```
import * as Y from 'yjs'
const docA = new Y.Doc()
docA.getText('note').insert(0, 'hello')

const update = Y.encodeStateAsUpdate(docA) // small binary diff
const docB = new Y.Doc()
Y.applyUpdate(docB, update)               // docB now says 'hello' too
```
