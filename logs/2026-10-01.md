# 📝 Daily Log — 1 October 2026

## 💡 Concept of the Day: WebAssembly (Wasm)

**The one-line version:** WebAssembly is a safe, portable, low-level binary format that lets code written in languages like C, C++, and Rust run at near-native speed, in the browser and beyond.

**How it works:**
- You compile source code to a compact `.wasm` binary, a portable target that is not tied to one CPU or operating system.
- A runtime validates the module and runs it in a sandboxed, memory-safe environment with isolated linear memory.
- In the browser, Wasm runs alongside JavaScript in the same virtual machine, and the two can call each other: Wasm handles heavy compute, JavaScript handles the UI.

**Why it matters:** JavaScript is flexible, but CPU-heavy work like image and video editing, 3D games, and in-browser inference can bottleneck. Wasm gives that work a fast lane without leaving the web platform, and the same modules can run on servers and at the edge.

**A bit of history:** First released in March 2017, WebAssembly became a W3C Recommendation on 5 December 2019, with the standard maintained through the W3C WebAssembly groups and all major browser vendors involved.

## 🛠️ Tool of the Day: Wasmtime

- **What:** Wasmtime is a standalone runtime for WebAssembly, WASI, and the Component Model from the Bytecode Alliance. Use it as a command-line tool or embed it as a library in a larger application.
- **Why it is useful:** Through WASI, modules get a secure, portable way to access filesystems, networking, clocks, and random numbers. Wasmtime is built on the Cranelift code generator for speed, with a strong focus on correctness, security, and configurable CPU and memory limits.
- **Try it:** Install the CLI, compile a tiny Rust program to Wasm, then run it outside the browser:

```
curl https://wasmtime.dev/install.sh -sSf | bash
rustup target add wasm32-wasip2
rustc hello.rs --target wasm32-wasip2
wasmtime hello.wasm
```
