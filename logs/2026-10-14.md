# 📝 Daily Log — 14 October 2026

## 💡 Concept of the Day: Conventional Commits — a Grammar for Your Git History

**The one-line version:** Conventional Commits is a simple convention — `<type>(<scope>): <description>` — that makes your git history readable by humans *and* machines.

**The idea:** `git commit -m "fix stuff"` tells future-you nothing. A conventional message like `fix(auth): handle expired token gracefully` tells everyone the *kind* of change (feat, fix, docs, style, refactor, perf, test, chore, ci, revert), the *area* (the scope in parentheses), and the *what* (a short imperative description). Breaking changes get a `!` (`feat!: drop v1 endpoints`) or a `BREAKING CHANGE:` footer.

**Three things that matter in production:**
- **Machines can read it** — CI can decide the version bump from commit types: `feat` → minor, `fix` → patch, breaking change → major. Tools like semantic-release turn a well-formed history into automatic releases and changelogs.
- **History becomes searchable** — `git log --grep="^fix"` finds every bug fix; scope (`fix(payments):`) narrows it to the right module. That beats grepping through prose.
- **It scales to teams** — a shared vocabulary ends the "fixed the thing / wip / stuff" era. New contributors read one page and write commits the whole team understands.

## 🛠️ Tool of the Day: commitlint — Never Let a Bad Commit Message Land

**What it is:** commitlint lints your commit messages against the Conventional Commits rules and rejects ones that don't follow the format. It runs as a Git hook, so the check happens before the commit is even created.

**Why it's useful:**
- Conventions only work when they're enforced — a hook is cheaper than a code-review comment every time
- Bad messages get caught at your keyboard, not after a PR is already open
- Pairs perfectly with automated release tools: if the commits are clean, changelogs and version bumps generate themselves

**How to try it:**
```bash
# install the linter and the conventional config
npm install -D @commitlint/cli @commitlint/config-conventional husky

# the one-line config
# commitlint.config.js
module.exports = { extends: ['@commitlint/config-conventional'] }

# run it on every commit message
npx husky init
echo "npx --no -- commitlint --edit \$1" > .husky/commit-msg
```
Now try `git commit -m "stuff"` — commitlint rejects it and tells you what was wrong. Rewrite it as `fix: correct retry delay` and it passes.
