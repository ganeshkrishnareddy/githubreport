## 💡 Concept of the Day

### Cursor Pagination — the bookmark that never loses your place

An API rarely returns a whole dataset at once. Instead it hands you one page at a time — and how it marks "where you left off" matters more than most developers expect.

**Offset pagination** is the classic approach: `?page=3&limit=20`. The database skips the first 40 rows and returns the next 20. It is simple and lets users jump to any page — but it has two real flaws. First, deep pages get slow: `OFFSET 500000 LIMIT 20` still makes the database read and discard 500,000 rows. Second, it is unstable: if a row is inserted or deleted while you are paging, the window shifts — items appear twice, or silently vanish.

**Cursor pagination** fixes both. Instead of a page number, the client passes an opaque token — usually called `after` — that marks the last item seen:

```
GET /api/orders?limit=20&after=eyJpZCI6MTIzfQ
```

The server decodes the cursor (typically the last item's sort key plus its id) and seeks straight to that position with an index lookup. Page 500 costs the same as page 1, and new rows inserted elsewhere cannot shift your place in the list.

The trade-offs: you cannot jump to page 47 — you can only walk forward from a known point — and a total page count is usually impractical to report, so responses carry `has_more` instead. Rule of thumb: use cursors for feeds, infinite scroll, and any large or fast-changing list; keep offset for small, mostly static tables where "go to page N" is a real feature.

## 🛠️ Tool of the Day

### HTTPie — curl, but built for humans

**HTTPie** is a command-line HTTP client designed for the API era: JSON is the default, output is syntax-highlighted, and requests read like plain language instead of a wall of flags.

```bash
# install: brew install httpie  (macOS) or pip install httpie
http GET api.example.com/orders limit==20
http POST api.example.com/orders name=Keyboard price:=49
http GET api.example.com/orders "Authorization:Bearer TOKEN"
```

Compare that with the equivalent curl — no `-H` flags, no manual JSON quoting, and the response comes back colourised and pretty-printed.

Why it is worth trying:

- **Explore paginated APIs fast.** Add `after==<cursor>` to walk through pages and watch the `has_more` flag flip, without writing a throwaway script.
- **Readable by default.** Headers, JSON bodies, and status are formatted for humans — great for debugging an endpoint in the terminal.
- **Sessions and auth built in.** Named sessions persist cookies, and `-a user:pass` handles basic auth in one flag.

How to try it: install it, then point it at any public API — `http https://api.github.com` is a good first call.
