## 💡 Concept of the Day

### Database Indexes — the shortcut that saves full-table scans

Without an index, finding one row means a sequential scan: the database reads every row and checks it against your `WHERE` clause. That cost grows linearly with table size, so a query that felt instant on a thousand rows can crawl on ten million.

An index is a separate, sorted data structure that maps column values to row locations. Most relational databases use a B-tree (usually a B+tree): keys stay sorted across balanced pages, so a lookup walks from root to leaf in logarithmic time instead of scanning everything. Once positioned at the right leaf, a range query (`BETWEEN`, `>`, `<`) can simply walk sideways across linked leaves.

The trade is real, and it is the whole point:

- **Reads get fast** — lookups and sorts on the indexed column skip the full scan.
- **Writes get slower** — every `INSERT`, `UPDATE`, and `DELETE` must also maintain each index on the table.
- **Storage grows** — each index is a sorted copy of part of the data.

So index the columns you actually filter, join, or sort on, and check the query plan (`EXPLAIN ANALYZE` in Postgres) before adding one. An index on a column nobody queries is pure cost with no benefit.

## 🛠️ Tool of the Day

### lazygit — a simple terminal UI for git commands

[lazygit](https://github.com/jesseduffield/lazygit) is a terminal UI for git, written in Go. It puts status, files, branches, commits, and stash in keyboard-driven panels, so staging hunks, amending, squashing, and resolving conflicts stop being a memorised flag parade.

Why it is useful:

- Stage individual lines or hunks, not whole files, with a keypress.
- Browse commit diffs, check out recent branches, and push or pull without leaving the terminal.
- Every action shows the exact git command it ran, so you learn the CLI while using the UI.

How to try it:

```bash
brew install lazygit
# or: go install github.com/jesseduffield/lazygit@latest
cd your-repo
lazygit
```
