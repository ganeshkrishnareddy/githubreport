## 💡 Concept of the Day: The Circuit Breaker Pattern

**The one-line version:** A circuit breaker is a reliability wrapper around a remote call that stops hammering a failing service: it "trips" after repeated failures, fails fast instead of waiting, and periodically lets one request through to test whether the service has recovered.

**How it works:**
- Three states: **closed** (requests flow normally), **open** (calls fail immediately without touching the broken service), and **half-open** (one trial request is allowed through; success closes the circuit again, failure re-opens it).
- It pairs with timeouts and retries: retries probe gently, the breaker decides when probing becomes harmful.

**Why it matters:** Without one, a single slow dependency can pile up threads and connections until your whole service cascades into failure. With one, the failure stays isolated, dashboards light up clearly, and recovery is automatic.

**A bit of history:** Michael Nygard popularized the pattern in *Release It!* (2007), drawing the analogy from electrical fuses; Martin Fowler’s 2014 write-up made it standard vocabulary, and it is now built into resilience libraries in nearly every ecosystem (Resilience4j, Polly, and friends).

## 🛠️ Tool of the Day: k6

- **What:** k6 is an open-source load-testing tool (from Grafana Labs) that lets you write performance tests in JavaScript and run them against APIs to find breaking points before your users do. Home: https://k6.io
- **Why it is useful:** Instead of guessing whether your circuit-breaker and retry settings actually hold under load, k6 simulates hundreds or thousands of virtual users, ramps traffic, and reports latencies, error rates, and thresholds. It is the practical way to prove a resilience story instead of theorizing about it.
- **Try it:** Install it and run a quick smoke test against an API:

```
k6 run --vus 50 --duration 30s script.js
```

```js
import http from 'k6/http';
import { check } from 'k6';

export default function () {
  const res = http.get('https://your-api.example/health');
  check(res, { 'status is 200': (r) => r.status === 200 });
}
```

Then add a threshold (e.g. `http_req_failed: ['rate<0.01']`) so the test itself fails when your error budget is blown.
